# 通檢

簡繁異體通用的本地文件檢索與管理工具（macOS）。

*A local file search and management tool for macOS in which Simplified, Traditional and variant Chinese characters match each other (e.g. 万历 finds 萬曆, 萬歷, 万暦), for file names and full text.*

## 下載安裝

到 [Releases](https://github.com/TsaichengLiu/tongjian-search/releases/latest) 下載 `TongJian-<版本>.dmg`（約 20 MB），打開後把「通檢」拖到「應用程式」。支持 Apple 芯片和 Intel 的 Mac，macOS 12 及以上；自帶 Python，不用另裝任何東西。

**第一次打開**：這個 App 沒有 Apple 開發者簽名，第一次雙擊時 macOS 會提示無法驗證、不讓打開。點「完成」關掉提示，打開「系統設置 › 隱私與安全性」，往下找到關於「通檢」的提示，點「仍要打開」並確認（可能要輸入登錄密碼）；之後就和普通 App 一樣雙擊打開。macOS 14 及更早也可以按住 control 點按「通檢」，選「打開」。請從「應用程式」裡打開，不要直接在磁盤映像裡運行。

索引和設置存在 `~/Library/Application Support/TongJian/`，縮略圖緩存在 `~/Library/Caches/TongJian/`；刪掉 App 和這兩個文件夾即完全卸載。

### 從源碼構建

需要 macOS 12 以上和 Xcode 命令行工具（提供 `python3` 與 `swiftc`；沒有的話在終端運行 `xcode-select --install`）。不依賴任何第三方庫。

```bash
git clone https://github.com/TsaichengLiu/tongjian-search.git
cd tongjian-search
./build_app.sh --install      # 構建並安裝到「應用程序」（用系統的 python3）；不加 --install 則只生成 build/通檢.app
tools/make_dist.sh            # 打包給別人下載的 build/dist/TongJian-<版本>.dmg：通用二進制、自帶 Python
```

`tools/make_dist.sh` 會下載 [python-build-standalone](https://github.com/astral-sh/python-build-standalone) 的 CPython（Apple 芯片、Intel 各一份，按固定版本和 SHA-256 校驗），合併成一份通用的，去掉 pip、Tk、IDLE 等用不到的部分（約 45 MB）。

## 使用

打開「應用程序」裡的通檢。點左上「資料庫 ＋」加入存放資料的文件夾，通檢會為文件名和全文建立索引。之後用 macOS 的 FSEvents 實時監聽：文件新增、修改、改名、刪除後幾秒內更新索引（在訪達裡改名、移動，收藏標籤備註都保留）；每次啟動時再快速核對一遍（約 3 萬個文件 3 秒左右）。實時監聽和定時重掃都只在 App 打開時進行，退出後沒有任何後台活動。默認只檢索文件名（含文件夾名），需要時在工具欄切到「名稱與全文」或「僅全文」。

- **匹配方式**：精確／簡繁／異體（⌘1/2/3）。「異體」模式下查「万历」可得 萬曆、萬歷、万暦、萬厤；跨行斷開的詞也能找到。
- **語法**：空格＝且，`|`＝或，`-詞`＝排除，`"…"`＝西文短語。
- **模糊檢索**（工具欄「≈ 模糊」，⌘4）：容許脫字、衍字、訛字，查「李自成攻陷京師」也可得「李自成陷京師」「李自成攻入京師」。按相似度（1 − 差異字數 ÷ 檢索詞字數，可選 50%–90%）篩選，空白、標點不計，3 字以上的詞才模糊匹配，排除詞仍按原方式；與三種匹配方式疊加使用。也可以貼一整句話，找它在資料庫裡被引用、轉錄的各處（容許異文）。算法為 Myers 位向量近似匹配；候選用 q-gram 原理預篩：檢索詞分成 n 段，每處差異至多破壞一段，近似出現處至少有 n − 差異數 段原樣保留，且這些段的相對位置相差不超過 2 × 差異數 —— 只是必要條件的篩選，不會漏掉符合相似度的出現處（字與字之間隔著七個以上符號的極端情況除外）。2 億字的資料庫上，短語一般 0.2–2 秒，一兩句話 1–2 秒；相似度設得很低時最多算 6 秒，先列出已找到的（按含檢索詞片段多少的順序覆核，最像的通常在前）；輸入新詞時舊的檢索立即停止。
- **限定範圍**：點側欄的文件夾只在該文件夾內檢索，⌘ 點擊可同時選幾個；在結果上右鍵「只在選中項中檢索」／「加入檢索範圍」可自選若干文件和文件夾（結果上方的「範圍」標籤可查看、移除）；預覽全文時 ⌘F 只在當前文件內查找，與上方檢索框互不干擾（查找框有自己的「模糊」開關）。
- **類型**：側欄「類型」每行一類（PDF、文檔、文本、電子書、表格、演示、圖片、音視頻、壓縮包、其他），用擴展名附標表示（DOCX、DOC、RTF……）；什麼都不選就是全部類型。點行選整類，點附標只選那一種擴展名，可多選，有選擇時沒選中的附標變淡；「+N」展開其餘擴展名，「＋」可輸入任意擴展名（如 `caj nh`）。
- **檢索歷史與保存的檢索**：點空的檢索框、框裡的時鐘圖標或按 ↓，下拉列出保存的檢索和最近的檢索（連同匹配方式、模糊、範圍和篩選），↑↓ 選、回車重跑。檢索停留三秒、按回車或打開了結果才記入歷史（打字途中的半截詞不記；同一個詞接著調篩選只留最後一條），最多 60 條，只存在本機資料庫裡，設置裡可關閉、清除。結果上方的 ☆ 把當前檢索保存到側欄「已保存的檢索」，右鍵可重命名、用當前檢索更新、刪除。
- **重複文件**：結果裡內容相同的文件合成一條（PDF 等有文字的比抽出的文字，其他按大小和頭、中、尾各 64 KB 比對），點「另有 N 個副本」展開，副本可照常預覽、操作；設置裡可關閉合併。側欄「重複文件」列出所有重複的組（按可騰出的空間排序，可按類型、文件夾縮小範圍），每組選留一份（默認建議不在「下載」裡、文件名較完整、較早的那份），其餘移到廢紙簍——移動前逐字節核對整個文件。
- **片段**：結果下方列出至多三段命中的上下文。檢索幾個詞時（如「方以智 賣菜」），先讓每個詞都至少露面一次，幾個詞同在一段的優先，再按出現的先後補足。
- **高亮**：黃底為原字命中，朱色下劃線為異體命中（原文字形與檢索詞不同），藍色下劃線為模糊命中裡與檢索詞不同的字。PDF 的命中片段標出頁碼，可一鍵跳到原件該頁。
- **PDF 原件**：逐頁顯示（後台用 PDFKit 只渲染視區附近的頁，離開視區即刪掉），黃底標出命中。先單擊選中結果裡的文件，再把鼠標停在它片段中命中的詞上，右側預覽（全文或原件）就跳到那一處；雙擊命中的詞在全文與原件之間來回跳（原件上用紅框標出）；全文其他位置可右鍵 →「在原件中查看此處」，原件上右鍵 →「在全文中查看這段」。可操作的命中在鼠標停留時會套上小框。只為視區附近的頁建元素，幾千頁的書打開也只要零點幾秒、內存不隨頁數增長。連續捲動，⌘＋滾輪或 ＋／− 縮放。原件上可以直接拖選文字、⌘C 拷貝（按全文取字，保留換行），右鍵可查詢、翻譯、檢索、附出處拷貝、在全文中查看；空白處拖動平移。標註和選字用的是 PDF 文字層的逐字位置；掃描件沒有文字層無法標註、選字，OCR 文字層本身位置不準時框也會略有偏移。
- **Word 原件**：Word（docx、doc）的「原件」由通檢按原文件重新排版：段落、字號、粗斜體、縮進、表格、圖片、文本框照原文件，腳註、尾註列在文後（點正文裡的註號跳過去）；按版心寬度連續排，分頁與 Word 不同。排版與全文、索引出自同一次讀取，所以命中標註、檢索片段懸停跳轉、雙擊命中在全文與原件之間互跳、選字拷貝、右鍵菜單都與 PDF 原件一樣。文件在上次掃描後改過的，照樣顯示，但要重新掃描後才標註、互跳。很長的文件（四十萬字以上）只排前一部分。doc（Word 97–2003）的正文和腳註由通檢直接從二進制文件裡讀，版式借 macOS 自帶的 textutil 轉換（只在打開原件時轉，一次約 0.1 秒，進程用完即退，不寫臨時文件）；textutil 不保留 doc 裡的圖片，原處顯示一個「圖」字佔位。rtf 等其他格式暫不支持。
- **掃描件**：幾乎沒有文字層的 PDF（平均每頁不到 20 個字符）默認顯示原件，全文裡連續的空白頁合成一行；側欄「無文字層」也包括它們。
- **文件夾**：文件夾名也參與檢索（例如存放古籍書影照片、文件名都是 IMG_xxxx 的文件夾）。點開後有兩種視圖：「結構」像訪達的列表視圖，子文件夾可逐層展開，每層附文件數、大小、日期，展開的上級文件夾在滾動時吸頂；當前檢索詞命中的名稱高亮，所在分支自動展開並滾到第一處，點「名稱命中 N 處」依次跳轉。「縮略圖」列出本層文件，照片文件夾默認用它。雙擊子文件夾進入，點文件看預覽、可返回原位置。縮略圖由 QuickLook 生成，按數據庫緩存在 `~/Library/Caches/TongJian/thumbs-…`。
- **排序**：文件夾和文件名按系統的排序設置（默認拼音；設置裡可改筆畫、部首、Unicode），數字按數值，卷、第、冊、年等編號裡的中文數字也按數值（卷二 < 卷十 < 卷一百，萬曆四年 < 萬曆十五年），書名裡的數字不動（三國志、二十四史仍按拼音）。
- **右鍵**：結果、側欄文件夾、文件夾樹、原件頁面各有自己的菜單；選中的文字和輸入框用系統菜單（查詢、翻譯、拷貝等），全文裡另有「在通檢中檢索」「在本文件內查找」「拷貝（附出處）」「在原件中查看此處」；按鈕、工具欄、空白處不彈菜單。
- **管理**：收藏、標籤、備註、重命名、移動、移到廢紙簍（可在訪達「放回原處」）、快速查看（空格）、在訪達中顯示（⌘R）。
- **自定義異體**：設置 → 每行一組互通的字（如「峯峰」），保存後自動重建索引。
- **恢復默認設置**：設置窗口左下角；自定義異體字和排除列表需另行勾選才會清除，資料庫、收藏、標籤、備註不受影響。

**去噪**：json、yaml、py、js、css、sql 等代碼與配置文件默認只收文件名；含 package.json、pyproject.toml、requirements.txt 等的代碼項目文件夾整個跳過；任何文件夾都可以右鍵「排除此文件夾」。這些都能在設置裡改。

支持全文的格式：txt/md/csv/html/json 等文本（自動識別 UTF-8、GB18030、Big5）、doc/docx/rtf/odt、epub、xlsx、pptx、帶文字層的 PDF。Word（docx）收正文（含表格、文本框）和腳註、尾註，不收「修訂」裡已刪除的文字、域代碼（超鏈接、目錄之類的指令）和域的二進制數據、圖形位置之類的內部數據；有注音（假名、拼音）的只收正文。Word 97–2003（doc）同樣收正文和腳註、尾註，不收域代碼。掃描版 PDF 只檢索文件名（側欄「無文字層」可列出）。日誌（.log）不收全文；json/csv/代碼等數據類文本超過 20 MB 只收文件名。

## 給 LLM 用：本地 MCP 服務

`app/tj_mcp.py` 是一個 MCP 服務（stdio），讓 Claude Code 等 LLM 客戶端直接用通檢的索引查資料：簡繁異體互通、可模糊、命中帶頁碼，返回片段而不是整篇，省 token。

```bash
# 從 Releases 下載的版本（自帶 Python）
claude mcp add --scope user tongjian -- /Applications/通檢.app/Contents/Resources/python/bin/python3 -B -s /Applications/通檢.app/Contents/Resources/app/tj_mcp.py
# 自己用 build_app.sh 構建的版本
claude mcp add --scope user tongjian -- /usr/bin/python3 -B /Applications/通檢.app/Contents/Resources/app/tj_mcp.py
```

- 工具：`search`（檢索，參數同界面：範圍、匹配方式、模糊、文件夾、類型、擴展名、標籤；內容相同的文件合成一條並列出副本路徑）、`find_in_file`（一個文件內各處命中的上下文和頁碼）、`read_file`（按頁或按字符位置讀原文）、`list_folder`（資料庫概況、文件夾結構）、`file_info`（含標籤、備註）、`variants`（查簡繁異體）、`list_tags`；寫操作只有 `add_tag`（加／去標籤）和 `append_note`（在備註末尾追加，不覆蓋）。不改名、不移動、不刪除文件。
- 只讀打開索引數據庫（SQLite `mode=ro`，寫入會被拒絕；兩個寫工具另開連接、用完即關），通檢開不開都能用，與通檢同時運行也沒問題。
- 由 LLM 客戶端在會話期間啟動，會話結束（標準輸入關閉）即退出；不常駐、不聯網、不需要 API key。空閒兩分鐘釋放緩存。
- 頁碼是 PDF 的頁序（p.N），不一定是書上印的頁碼。

## 資源佔用（約 3 萬個文件、3 億多字的資料庫實測）

- 後台服務實際內存（physical footprint）約 30–50 MB，界面（WebKit）60–100 MB；長時間使用不會累積（3000 次混合請求後線程、文件句柄、內存都持平）。
  關鍵是以 `MallocSpaceEfficient=1` 啟動 Python：否則 macOS 分配器會囤積釋放的大塊內存，預覽長文本後可達 300 MB 以上。
- 全文緩存上限 2000 萬字，空閒 5 分鐘清空（模糊檢索用的字表、去標點的名稱表同時釋放，下次用時幾毫秒重建）；空閒時每分鐘請分配器歸還內存。
- PDF 原件逐頁渲染：每頁起一個輔助進程（同時至多兩個），頁面圖和逐字位置一次算出，算完即退出；不用 WebKit 的 PDF 插件（它要把整本載入內存）；結果不寫磁盤，最近的頁面圖（上限 12 MB）和文字位置（上限 6 MB）留在內存，空閒 5 分鐘清空。界面只保留視區上下一屏內的頁面圖和標註。
- 界面的 WebKit 只用內存數據存儲，不在磁盤上留網頁緩存、LocalStorage 等（舊版在 `~/Library/Caches/local.tongjian.app`、`~/Library/WebKit/local.tongjian.app` 留下的目錄在啟動時刪除）；設置（含閱讀字號）存在資料庫裡。
- 建索引時大 PDF（>80 MB）逐個抽取，抽取進程以「實用工具」級優先級運行，單個進程實際內存最大約 120 MB。
- 磁盤：WAL 限制在 32 MB；每天空閒時整理一次（合併全文索引、空閒頁超過兩成且大於 32 MB 時壓縮數據庫、清理已刪文件和舊版本的縮略圖，縮略圖總量上限 300 MB）；日誌超過 2 MB 時輪換。
- 查重和結果合併用的內容指紋只在內存裡（約 4000 個候選文件約 1 MB），空閒 5 分鐘清空；第一次查重約 0.6 秒，之後 0.1 秒以內。檢索歷史最多 60 條。
- 文件名檢索用常駐內存的歸一化名稱表（2.8 萬個文件約 1 MB）預篩候選，再用正則覆核：2.8 萬個文件 1–12 毫秒；30 萬個文件建表 0.6 秒，檢索幾毫秒到 0.25 秒。

## 結構

```
app/server.py        本地 HTTP 服務（僅 127.0.0.1，帶令牌）
app/tj_core.py       SQLite 索引（FTS5，每個漢字一個詞元）、掃描線程、檢索、文件操作
app/tj_norm.py       字形歸一：精確 / 簡繁 / 異體 三級，一字對一字，長度不變
app/tj_fuzzy.py      模糊檢索：編輯距離近似匹配（Myers 位向量 + 鴿巢原理預篩）
app/tj_mcp.py        給 LLM 用的本地 MCP 服務（stdio，只讀打開索引）
app/tj_extract.py    各格式全文抽取
app/static/          界面（原生 JS/CSS，無構建步驟）
app/data/variants.json  歸一字表（由 tools/build_variants.py 生成）
macos/main.swift     App 外殼（WKWebView）
macos/tjhelper.swift PDFKit 抽取文字、移到廢紙簍
tools/build_variants.py  從 Unihan 18.0 + OpenCC 生成字表
```

- 測試模糊檢索：`python3 tests/test_fuzzy.py`（與暴力動態規劃逐處核對，確認不漏）
- 構建 App：`./build_app.sh`（生成 `build/通檢.app`）；`./build_app.sh --install` 同時安裝到 `/Applications`（App 運行中也可以執行；Python 改動在重啟後生效）
- 不用 App、在瀏覽器裡用：`python3 app/server.py`
- 重新生成字表：`python3 tools/build_variants.py`
- 索引數據庫：`~/Library/Application Support/TongJian/library.db`；日誌：`~/Library/Logs/TongJian.log`

## 字表

把 Unihan 的簡繁對應（kSimplified/kTraditionalVariant）、異體（kSemantic/kZ/kJapaneseNew/Old/kCompatibilityVariant）、OpenCC 的簡繁與日本、台灣、香港異體表，以及康熙部首、兼容漢字的 NFKC 映射合併，用並查集歸成等價類（約 1.78 萬字、8 千組）。

`kSemanticVariant` 常由罕用字居中，把不相干的規範字串成一類（如 敦—𠊋—龍、匝—𠂝—眾）。所以這條規則是：一條語義異體邊兩端所在的類若都已含規範字（GB2312 或 Big5），就不合併。`tools/sources/supplement.txt` 補了 Unihan 未收的舊字形（靑青、淸清、尙尚等）。

字表數據的來源與許可見 [tools/sources/README.md](tools/sources/README.md)。
